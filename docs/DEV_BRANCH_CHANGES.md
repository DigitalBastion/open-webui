# Open WebUI `dev` branch changes

> **Unreleased and unstable:** this report describes the official Open WebUI `dev` snapshot at [`336d8841f`](https://github.com/open-webui/open-webui/commit/336d8841f400213733283ada8ca6c5e3056be8f0) on 2026-08-24. It is development code, not a release, and may contain incomplete features, regressions, schema changes, or behavior that changes before reaching `main`. Do not treat it as production-ready without independent testing.

## Comparison scope

- Baseline: official `main` at [`01f4282f1`](https://github.com/open-webui/open-webui/commit/01f4282f1ffe0d6212f58d3afbeae21fffd0c4be).
- Development snapshot: official `dev` at [`336d8841f`](https://github.com/open-webui/open-webui/commit/336d8841f400213733283ada8ca6c5e3056be8f0).
- The branches diverge at [`483adf704`](https://github.com/open-webui/open-webui/commit/483adf7040f1dd8f1ad32e53908865d22e863778). There are 369 commits reachable from this `dev` snapshot but not the merge base, while `main` has 42 commits not reachable from this `dev` snapshot. This is therefore a comparison of two diverged snapshots, not a promise that `dev` contains every later `main` fix.
- Sources are repository history and code plus official GitHub commit/PR metadata. Generic `refac` commits are included only where their diffs introduce consequential behavior. Translation-only, mechanical refactors, CI-template work, and minor cosmetic noise are omitted.

## Chat, agents, and tool use

- **Tool execution can require explicit approval.** A new experimental tool-permissions mode (`ENABLE_TOOL_PERMISSIONS`, persisted as `chat.tool_permissions.enable`) can pause a saved chat before a tool call, persist the pending call, and let the user approve or reject it through a new resolution endpoint. This materially changes agent execution from fire-and-forget to resumable, user-gated execution. [`7d99b2716`](https://github.com/open-webui/open-webui/commit/7d99b2716a0472b2100b3a71825d8eb3fcbbe877)
- **Models can ask structured clarifying questions.** A new built-in `ask_user` tool pauses generation and displays one to three multiple-choice questions, optionally accepting free-form answers, before returning the answers to the model. It must be enabled as the model's **Ask User** built-in tool and requires an active browser/WebSocket session. [`4465f52a3`](https://github.com/open-webui/open-webui/commit/4465f52a3eb521854cf190f91b0ea7cf3fa21830), [`083e35144`](https://github.com/open-webui/open-webui/commit/083e35144152d6a301bed01aa6d898db3871ddcf)
- **In-progress Responses API output survives reloads more faithfully.** Active response state is stored in memory or Redis and overlaid when a chat is fetched; streaming is represented as typed Responses events, including reasoning and tool-call argument deltas. This improves reload/reconnect behavior and channel updates during long generations. [`a1579a01f`](https://github.com/open-webui/open-webui/commit/a1579a01ff43cacb357269707d36267ad35e01d6)
- **Several Responses API data-loss/crash paths are fixed.** `dev` preserves streamed output when `response.completed` supplies an empty output array, applies `response.output_item.done`, prevents delta-handler fallthrough crashes, tolerates reasoning items without `started_at`, and retains streamed text when providers or filters send non-string content. [`798f3935a`](https://github.com/open-webui/open-webui/commit/798f3935ae1a8155e6a72df7c70dcca9a1517dbe) ([#27800](https://github.com/open-webui/open-webui/pull/27800)), [`74a790282`](https://github.com/open-webui/open-webui/commit/74a79028211d556022945d442b68fe948e1fa096) ([#28310](https://github.com/open-webui/open-webui/pull/28310)), [`fc8a9b8ed`](https://github.com/open-webui/open-webui/commit/fc8a9b8ed6008daa7079f3c3353ce33f310ae4c6) ([#28312](https://github.com/open-webui/open-webui/pull/28312)), [`883c7434f`](https://github.com/open-webui/open-webui/commit/883c7434fb6196d01b12de9f8ce19bd9f0797cd6) ([#28872](https://github.com/open-webui/open-webui/pull/28872)), [`ac091273b`](https://github.com/open-webui/open-webui/commit/ac091273b7133299ff5e8bfa3b132a5cc15fe808) ([#28840](https://github.com/open-webui/open-webui/pull/28840))

## Terminal and file workspace

- **Terminal orchestrators gain explicit context isolation.** Admins can configure terminal access as shared, per-chat, per-automation, or off. Open WebUI sends `X-Terminal-Context-Id`, blocks unavailable contexts, and waits for a saved chat before opening a per-chat terminal. This is an important isolation and compatibility change for Open Terminal/orchestrator deployments. [`009999f36`](https://github.com/open-webui/open-webui/commit/009999f3636b1a3451f8fe55232e6ab132a64e66)
- **The terminal file browser is substantially expanded.** It has a redesigned browser, file-type icons, bulk operations, previews, editable text/code files, pan/zoom, hidden-file handling, and filename/content search with pagination and jump-to-match behavior. The corresponding terminal server must support newer `/files/search`, `/files/glob`, and `/files/matches` APIs for all capabilities. [`2dadc5435`](https://github.com/open-webui/open-webui/commit/2dadc5435af77b0638af69200e3af1b9654417b6), [`7dfbdd221`](https://github.com/open-webui/open-webui/commit/7dfbdd221ac0f7a839dd049e3e82b6a84c316860), [`7abe11346`](https://github.com/open-webui/open-webui/commit/7abe11346a1cc309da2c3fcec2f61faaeb47b96a)
- **Terminal files can be attached through `@` search.** The composer searches the selected terminal filesystem and attaches file/directory paths as filesystem context without trying to ingest them into RAG. [`d17f06a23`](https://github.com/open-webui/open-webui/commit/d17f06a23501e5c39cf98d9c9642178da25343fb)
- **Terminal `display_file` results can render inline.** Models can request `inline=true`; chat messages can preview images, audio/video, PDF, SQLite, Office, HTML, and text/code files directly. A user setting chooses inline versus sidebar display by default for direct terminal servers. [`78f48a21e`](https://github.com/open-webui/open-webui/commit/78f48a21eef330c0b78c33f2b5fc2169b084997c), [`e623c02ac`](https://github.com/open-webui/open-webui/commit/e623c02acc70c4ee5d7f2eb2f32d9b7f39287663)
- **Terminal/tool-server failure handling is quieter and safer.** Terminal proxy disconnects are handled, and terminal/tool-server connectivity failures are logged as concise messages rather than full tracebacks. [`6b4131d1d`](https://github.com/open-webui/open-webui/commit/6b4131d1d73ca3695baadd0ab247688357b15b63) ([#27755](https://github.com/open-webui/open-webui/pull/27755)), [`fd7024f19`](https://github.com/open-webui/open-webui/commit/fd7024f198122f69dc2360988f184dcd20335c72) ([#27757](https://github.com/open-webui/open-webui/pull/27757))

- **Three database migrations run on upgrade.** They add a `(user_id, group_id)` group-member index, repair double-encoded OAuth identity data, and add chat/timer indexes plus `timer_at`. Back up the database and budget migration time, especially for large chat tables. ## Suggested validation before adopting this snapshot

1. Clone production data and time all three migrations, especially on SQLite and large chat/message tables.
2. Exercise OpenAI Responses and Anthropic passthrough streaming through reloads, reconnects, reasoning, tools, and filters.
3. If enabling tool permissions or Ask User, test saved-chat resume, rejection, browser disconnect, multiple workers, and Redis-backed deployments.
4. Validate Open Terminal server API compatibility, context isolation, filesystem search, inline previews, and automation contexts.
5. Reindex knowledge, metadata search, and memories after any embedding-model change.
6. Recheck OAuth/OIDC/SCIM login, group sync, session revocation, and audit events against the production identity provider.
7. Review new environment defaults, container package removals, DNS behavior, and licensing/branding requirements before rollout.
